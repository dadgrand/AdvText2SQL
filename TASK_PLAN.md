## 1. Правила, которые действуют для всех задач

1. **Никакой контаминации.** dev-217, OOD-876, новый PG-hard тест и любые внешние
   тестовые схемы не попадают ни в один обучаемый файл. Проверка — тестами, а не
   обещанием.
2. **Одна строка на запуск.** Каждый обучающий прогон отчитывается полем:
   модель/revision, precision, targets, r/alpha/scaling, LR, supervised tokens,
   optimizer steps, dev-метрика, критические ошибки, GPU-часы, peak VRAM.
3. **Число без знаменателя не публикуется.** Срезы: 217, 241, OOD-876, PG-hard,
   внешний тест — у каждого свой знаменатель.
4. **Доставка — коммиты в `lora_track` форка.** PR в `origin/main` не делаем.
5. **Отрицательный результат фиксируется.** Если гипотеза не подтвердилась — это
   запись в отчёте с числом, а не тишина.

- Сервисные поля — в sidecar, в student-prompt не попадают.

- Три семантических кейса: `WITH`, quoted identifier, деление с явным PG-cast —
  должны дойти до labels.
- Статистика: p50/p95/p99 длин контекста и ответа, доля усечённых, доля примеров
  с нулём loss-токенов.
- Артефакты: `loader.py`, `renderer_parity.py`, `cluster/batch_report.json`.

### Волна 2 — численность и первый обучаемый прогон

#### t20. Численная корректность и packing — `trainer`
Статус: pending. Зависит от **t10**.
- Эквивалентность накопления градиента: один шаг на одном батче против неравных
  микробатчей (dropout=0) — градиент должен равняться сумме NLL, делённой на число
  валидных target-токенов шага.
- Учёт target-токенов: `(labels[...,1:] != -100).sum()`.
- Packing только после непакованного baseline: менять содержимое A при той же длине,
  логиты B не меняются; маска на границе примеров.
- Артефакт: `cluster/runs/numerics_report.json` с вердиктом по каждой проверке.

#### t14. Прогоны A и B на 7B — `trainer`
Статус: pending. Зависит от **t10**, **t11**.
- A: база Qwen2.5-Coder-7B-Instruct без адаптера, тот же prompt/evidence/decoding.
- B: только real train из native-PG loader; рецепт ветки: all-linear, r=16, alpha=32,
  dropout 0,05, LR 1.5e-4, cosine, warmup 0,03, effective batch 16, completion-only,
  packing off, seq 2048, microbatch 1 × accum 16.
- Инструментация обязательна: адаптированные модули и trainable count, нулевая поправка
  на старте, конечные градиенты, изменённые веса адаптера при замороженной базе,
  supervised tokens/шаг, grad norm до клиппинга, peak VRAM, wall-clock до лучшего
  чекпойнта, промежуточные чекпойнты.
- Артефакты: `cluster/runs/runA_base7b.json`, `runB_real7b.json` + предсказания.

## 7. Риски и контрмеры

| Риск | Контрмера |
|---|---|
| Судья систематически слеп (та же локальная модель) | слепая выборка, проверка находок по данным, второй контур — мой код |
| Генерация даёт красивый, но пустой результат | фильтр по исполнению, два прогона на стабильность, фикстуры |
| Утечка eval-схем в обучение | тесты t9 падают на любом пересечении |
| Низкий accept-rate пилота | отчёт по причинам отказов, правка промптов по классам брака |
| Время: протокол на недели | волны; к встрече — что успело закрыться с артефактом, остальное честно «в работе» |
| Числа несопоставимы | один харнесс, парные тесты, знаменатели у каждого среза |
