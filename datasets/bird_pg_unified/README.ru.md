# BIRD в PostgreSQL — объединённый датасет (17.11.2026)

Сведены две ветки правок одной и той же базы:

- **`advtext2sql-lora`** (наша) — перевод SQL через AST, сверка SQLite ↔ PostgreSQL
  построчно, отчёт о двух дефектах данных на сервере, синтетический корпус с
  политикой обработки `LIMIT`;
- **`bird-pg-reviewed-20261117`** (коллеги) — 12 смысловых исправлений dev,
  повторное исполнение каждого train-эталона дважды, разбор конфликтов
  «вопрос ↔ evidence ↔ SQL», очередь из 4 081 синтетической строки.

Это не объединение файлов: у каждой конфликтной строки есть решение и причина.
Оба исходных пакета сохранены отдельно, ничего не перезаписано.

**Взято у нас:** перевод SQL, сверка SQLite↔PostgreSQL, находка двух дефектов на
сервере (потерянные ведущие нули в `california_schools`, надмножество `toxicology`),
политика `LIMIT` (2 082 пустых ограничения сняты, 2 494 пары с реальным лимитом
вынесены), схема с `UNIQUE`.

**Решено без конфликта:** 1 422 флага «неназванный `LIMIT`» из их очереди
относились к строкам, где мы доказали, что ограничение пустое — они помечены как
снятые, а не как открытые.

## Как проверять

```bash
python tools/verify_dataset.py .                     # структурные проверки, без БД
python tools/verify_dataset.py . --db-host 127.0.0.1 --db-port 5444 \
    --db-user readonly_user --db-pass "$DB_PASS" --check-hashes
```

Проверено при сборке: dev — **217/217** исполняются, ни одна не пустая; 10
исправленных строк дают непустой результат; выборка train 240 строк по 57 базам
дала **240/240** исполнений и полное совпадение числа строк с их записью проверки.

## Что осталось открытым

- Смысловая сертификация **всех** строк не выполнена ни нами, ни коллегами: у двух
  сторон разные инструменты, и «согласовано» здесь означает «нет найденного
  противоречия», а не «доказано».
- 24 исключённых dev-строки — это 10 % бенчмарка. Метрика на 217 строках не
  сравнима напрямую с публичной на 241; для сравнения с прошлыми числами считайте
  обе.
- train-строки не сверялись с SQLite (для 63 баз нет локальных копий) — только
  PostgreSQL, дважды.
- Синтетика остаётся вспомогательным корпусом: 2 815 активных пар против 5 110
  реальных, и в основном корпусе она не проверялась round-trip прогоном.
