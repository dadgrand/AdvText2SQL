# Организация проекта — 23.10.2026

В `research_results/` перенесены три папки результатов из корня. Содержимое
725 исходных файлов проверено по SHA-256 до и после переноса. Корневые
экспортированные JSON-снимки отдельно сохранены в `legacy_snapshots/`.
Исторические планы из `local/old` сохранены в `legacy_notes/`.

43 существующих файла, чьи пути присутствуют в `main`, не редактировались и
не удалялись: проверены относительно текущего рабочего содержимого до уборки.
Изменения между ветками не откатывались к main.

Удалены только подтверждённые устаревшие инструменты и кэши:

- `local/run_check.sh`: вызывает отсутствующий `check_ambrosia_dbs.py`;
- прежний `local/old/test.py`: одноразовый черновой API-вызов с зашитым ключом;
- `scripts/probe_ambiguity.py` и `scripts/probe_main_ambiguity.py`: одноразовые
  пробы; второму уже не хватало исходной A/B-папки до начала организации;
- `.DS_Store`, `.ruff_cache`, проектные `__pycache__` вне `.venv`.

Рабочие исторические инструменты абляций сохранены с новыми путями результатов.
`research_paths.py` разрешает прежние пути из metadata и команд; при проверке
идентичности запуска нормализуется только расположение source_run, но hashes
данных, флаги и остальные параметры по-прежнему должны совпадать.

Проверки: 14 офлайн-тестов, Ruff, синтаксис всех shell-скриптов и PowerShell
monitor, четыре dry-run конфигурации (BIRD baseline 241, Ambrosia hybrid 227,
BIRD no32/33 full 241 и diagnostic 50), относительные ссылки новых документов.
API и БД для проверок не вызывались. Для переноса заблокированной папки закрыт
оставшийся SSH-watchdog завершённого запуска; новые запуски поднимают туннель сами.

`integrity_verification.json` — итог проверки, `main_files_before.json` — hashes
защищённых файлов, `result_file_manifest.json` — старые/новые пути и hashes
сохранённых результатов, `removed_files_and_caches.json` — список удалённых
служебных целей. Старые ссылки внутри исходных архивных отчётов сохранены как
исторические записи; новые точки навигации находятся в `docs/`.
